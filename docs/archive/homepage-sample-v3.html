为什么 Agent 需要一层独立的工具路由

把 LLM 接进生产系统之后，最先失控的往往不是模型本身，而是工具调用的组织方式。当工具数量从 3 个涨到 30 个，注册、鉴权、超时、重试这些横切关注点会散落在每个 handler 里，任何一次改动都要全文搜索。

tool-router 的思路是把路由层单独抽出来：声明式注册描述每个 tool 的 schema 与代价，调度器负责并行分发与结果聚合。这样 LLM 看到的永远是同一张「工具表」，而实现细节可以自由替换。
