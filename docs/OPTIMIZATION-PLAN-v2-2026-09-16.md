## 1. 设计原则（4 条，均可验收）

1. **反馈的范围等于可操作的范围。** hover、光斑、指针只出现在真实可点的元素上；无动作处保持安静。这条同时是无障碍底线。
2. **一件事只说一次。** 同一信息（栏目名、计数、入口）在一屏内只出现一次；第二次出现即模板填位。
3. **先读到，再认出。** 任何视口（桌面与移动端）下，列表页首屏无滚动须露出首条内容；辅助结构不先于内容出现。
4. **删手续，不删呼吸。** 删减前导后保持页面节奏，不顺手压紧留白；深色主题的光谱、行号、琥珀色、dmesg、字符签名是受保护资产，只削减重复出场，不削减本身。

## 2. P0 — 信任层（先于一切审美改动）

### T-1 主题切换滚动与锚点保持
- **现状**：`Nav.astro:84-93`，首页切换主题时 `history.replaceState` 清掉 hash 并 `scrollTo(0)`。深浅首页是两套组件树、section 高度不同，无 DOM 重建，只有 CSS 分支切换。
- **处置**：切换时记录当前 scrollY 与（若有）hash 对应的锚点 id；切换后按锚点 id 重新定位（两主题共用 `#projects`/`#recent` id，可直接映射），无锚点时恢复 scrollY；不再清除 hash。
- **验收**：在首页 `#projects` 区域中部切换主题，切换后 `#projects` 区仍在视口内（同一锚点内容可见）；URL hash 保留。非首页切换主题滚动位置不变（现状已正确，回归确认）。**不采用像素阈值**——深浅版式高度不同，绝对 scrollY 无意义，按锚点可见性验收。

### T-2 TOC 高亮保持
- **现状**：`ArticleLayout.astro:265` 附近，scrollspy 取 `visible` 集合中文档序最靠上的标题；长段落期间所有标题都滚出 rootMargin 窄带，`current=null`，全部目录项失去高亮——阅读辅助在中途说谎。
- **处置**：`visible` 为空时保持上一次高亮，直到下一个标题进入窄带接替。
- **验收**：在任一章节的长段落中部停留，其目录项保持高亮；滚动进入下一节后高亮转移。移动端（折叠 details）与桌面端行为一致。

### T-3 归档搜索／筛选状态机定义与修复
- **现状**：搜索（Pagefind UI）与筛选 chips、时间线是并存区域，无统一状态。用户无法判断「选了笔记再搜索」搜的是什么；moment 无独立 URL，不进 Pagefind 索引。
- **处置**（A-1）：定义三态状态机——
  - **默认态**：时间归档，chips 可筛（全部/笔记/随想）。
  - **搜索态**：输入搜索词即收起时间线，结果区独占；结果区顶部明示「全站搜索 · N 条」，chips 在搜索态下隐藏（避免暗示可叠加）。清空搜索词回到默认态。
  - **URL 同步**：`?search=1` 进入时聚焦输入框（现状保留）。
- **处置**（A-2）：小记不进 Pagefind 索引是结构性限制（无独立页面）。**不做**索引注入等 Hack；改为搜索态结果区底部追加一行静态提示「小记未纳入搜索，浏览全部小记 →」链至 `/thinkings`。
- **验收**：① 输入任意词 → 时间线收起、仅见结果区与范围说明；② 清空 → 时间线恢复且 chips 筛选态保持；③ 选「随想」再搜索，结果区文案不含「笔记」暗示；④ 搜索结果不承诺含小记，提示链接可达 `/thinkings`。

## 4. P1 — 注意力与可读性

### H-1 浅色首页开场收敛
- **现状**：`Hero.astro:10-24` 头像＋名字＋"Explore and build."（闪烁组件 `FlickerTitle`＋光标 `_`）＋「记录一些想法与实践。」＋`[ 关于我 ]` 按钮＋统计行（N 篇记录 · N 个项目 · 更新于）。头像链 `/about`、按钮链 `/about`、统计中「N 个项目」链 `#projects`。
- **处置**：
  - 删 `[ 关于我 ]` 按钮（`intro__actions`）——头像已承担 About 入口，首屏最明确的行动不应是「离开阅读」。
  - 删 "Explore and build." 整行（含 `FlickerTitle` 与光标）——通用口号，与已删的 pill CTA 同属「最不 Monostich」的残留。
  - 统计行**保留但降权**：它同时是 `#projects` 与 `/archive` 的功能性入口（删了它，`/#projects` 在浅色首页只剩导航一个入口）。保留链接、去掉「更新于」字段（由列表本身证明活跃）。
  - 「记录一些想法与实践。」保留——这是签名式开场的中文说明。
- **验收**：DOM 无 `intro__actions`、无 `FlickerTitle`；1440×900 与 390×844 首屏均露出「随想」区至少一行短句；`/#projects` 在浅色首页仍有 ≥2 个入口（导航＋统计行）。

### H-2 浅色首页近期列表日期左移
- **现状**：`index.astro:69-88` recent-row 为「序号＋标题/摘要＋右侧日期」，居中版心。Notes 页（全站公认最合适）是「112px 日期侧栏＋标题/摘要」。
- **处置**：浅色首页「文章」「实验室」两个 `recent-list` 复用 Notes 的行制式——日期从右侧移到左起 112px 侧栏位，标题左对齐成为扫描起点，序号删除（日期已是有序信息）。**深色 gutter 行不动**（`DarkHomeRecent.astro` 的行号体系是深色自有语言，两处不互相污染）。
- **不做**：不改动 Notes 页本身（它是对的）；不把摘要删掉（首页摘要承担补题职责，与列表页不同）。
- **验收**：桌面端日期在左、标题左对齐；移动端（≤700px）日期退到标题上方或行内前置，不出现右侧悬空日期。视觉回归仅这两个区块，Notes 页零变化。

- **现状**：`index.astro:56-57` 模块头「随想」＋「小记 →」，blockquote 本身也链 `/thinkings#id`。
- **处置**：删「小记 →」（模块头链接与区域标题同指一栏）。短句链接保留。

### H-4 Thinkings 标题与点击预期
- **现状**：`thinkings.astro` 整块 `article.thinking` 有 hover 反馈但只有标题和「阅读全文」可点；`dark.css:46` thinking 标题 40px vs 正文 16px。

  2. 再删「阅读全文 →」（`thinking__read`）。
  3. hover 反馈限定到标题链接本身，整卡不再响应 hover。
  4. 深色 thinking 标题 40px → 30px（`dark.css:46`），与文章 h2 的新档位（T-4）拉齐；`thinking__moment-title` 28px 不动。
- **验收**：DevTools 强制 `:hover` 下卡片非链接区域零变化；键盘 Tab 可达标题且有 `:focus-visible` 样式；「阅读全文」删除后标题静止态与正文标题可区分；深色标题与正文层级差 ≤2 档。**「阅读全文」的删除必须与标题可辨识在同一提交内完成**（中间态不进主干）。

  - `.article__content` 正文 16→17px、行高 1.7→1.8；`dark.css:48` 的 `.thinking__body .prose-zh` 同步。
  - `.article__content h2` 36→30px、h3 21→19px。
  - 信息类小字（日期、返回、TOC）从 `--text-faint` 提到 `--text-muted`；`--text-faint` 仅保留给装饰性行号、gutter。

### A-3 归档计数与日期去重
- **现状**：`archive.astro:98,110` 顶部「N 篇内容」＋年份组内 `archive__year-count`，筛选时计数三层同时变化。

### AR-1 文章头部精简

## 5. P2 — 人格与收尾

### G-3 动效收束
- 删 `FlickerTitle`（随 H-1 完成）；About 联系方式的 `data-scramble` 解码保留**首屏一次性**（是深色人格的浅色延伸），但列表逐项 `reveal-delay` 上限统一收到 ≤300ms（`index.astro` 现状 `min(index*60, 240)` 已合规，`thinkings.astro` 的 300ms 已合规，本项主要是**锁定现状并加回归**，不再新增逐项延迟）。
- **验收**：`prefers-reduced-motion` 下全部静止（现有 global.css 规则回归）；任何列表末项入场总延迟 ≤300ms；普通文本、日期、联系方式无持续动画（FlickerTitle 删除后达成）。

### G-4 胶囊导航形态固定
- **现状**：`Nav.astro:135-136` 滚动后 `max-width` 1140→980、加玻璃背景与边框，宽度/形态随滚动变化。
- **处置**：保留玻璃质感（深色下是成立的）但**去掉宽度变化**——滚动前后 `max-width` 恒定，只保留背景/边框的出现。`--nav-height` 的 compact 变化（`global.css:170`）同步评估，避免布局抖动。
- **验收**：滚动越过阈值后导航水平尺寸零变化（录屏对比）；无 `max-width`/`width` transition 作用于尺寸属性；移动端不受影响（700px 下本就通栏）。

### G-6 字体注释与 token 一致性
- **现状**：注释体系描述 Fraunces 衬线，实际 `--font-heading` token 指向需核实；审计 #14 已收拢 h1 token（3b75569）。

- **验收**：`grep` 字体相关注释与 token 值一一对应；无新增衬线引用。

### AB-1 About 作者语言（占位，待作者落笔）
- 浅色 About 首段加占位「这里等待补充」，由 Aloha 本人替换为 2–3 句话（为什么写、Monostich 意味着什么），合计 ≤100 字。Monostich 的含义至少出现一次。
- **这是全方案唯一新增内容项，也是唯一阻塞于作者的项。** 不补履历、技能条、时间线。
- **验收**：占位文本存在或已被替换；无新增结构性模块。

## 6. 移动端验收清单（每条 P1/P2 必须过）

| 改动 | 移动端风险点 | 验收 |
|---|---|---|
| H-1 删 Hero 元素 | 首屏更空，节奏是否塌陷 | 首屏露出随想短句一行 |
| H-2 日期左移 | 112px 侧栏在 390px 是否挤压标题 | 日期退让规则生效，无右侧悬空 |
