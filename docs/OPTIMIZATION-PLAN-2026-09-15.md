## 一、根因合并与设计原则

### 1.1 问题归结为五个根因

| 根因 | 描述 | 对应问题（合并后） |
|---|---|---|
| **R1 注意力倒置** | 辅助结构比内容更早、更强地出现 | 首屏先「认识作者」后「阅读作者」；页面前导把手续排在第一项内容之前；Dark 文章 36px 标题压过 16px 正文；Projects 四列与写作争夺篇幅 |
| **R2 重复承担** | 同一信息由多个元素各说一遍 | 返回链接＋英文路径；归档三层计数；年组内重复年份；已筛选仍标注分类；「随想」＋「小记 →」双入口；「返回笔记」＋「/ 笔记」 |
| **R3 反馈与可操作性脱节** | 表演出现在没有动作的地方 | Thinkings 整块 hover 但只有标题可点；静态项目的 hover 光斑与闪烁状态灯；Light 口号持续闪烁；普通信息执行解码；列表逐项 1200ms 入场 |
| **R4 通用人格替换具体人格** | 用「程序员符号」描述一个不存在的作者，而非 Aloha 本人 | Explore and build；「一些简单的笔记整理」；`/dev/curiosity`、`sleep.service not found` 启动日志；「开发中/进行中」状态词；Monostich 从未进入叙事 |
| **R5 双主题共享实现的工程泄漏** | 一套内容两套渲染＋零散 JS 状态，正确性债务外显 | `#projects` 双 id 锚点失效；Dark 首页遗漏最新小记；主题切换强制回顶并删 hash；搜索与筛选作用域分离；TOC 高亮中途消失 |

**关键判断**：R5 是「网站在说谎」，R1–R3 是「网站在啰嗦」，R4 是「网站在装别人」。优先级必须按这个顺序排——链接可信度是一切审美的前提。

### 1.2 核心设计原则

1. **先读到，再认出。** 访客在做出任何点击之前，应当先确认「这里有人持续在写」。名字、头像、统计的作用是署名，不是开场白。
2. **一件事只说一次。** 信息允许出现一次。第二次出现时它不再是信息，而是模板填空位——读者会立刻意识到「这是结构，不是人」。
3. **反馈的范围等于可操作的范围。** hover、光标、动效只出现在真实可点的位置。没有动作的地方保持安静。这条同时是无障碍底线：affordance 不说谎。
4. **删手续，不删呼吸。** 前导（返回、路径、宣言、计数）是进入内容的成本，做减法；空白是阅读的节奏，原量保留。删除前导后先保持页面总高度再观察，不顺手压紧。
5. **人格来自具体内容，不来自符号。** 光束、行号、琥珀色可以留——它们是氛围；但描述作者的必须是作者真实的短句、摘抄和关于写作动机的话。Monostich 作为站名至少要在叙事里被解释一次。
6. **两套主题共享底线，不共享性格。** 内容完整性、导航可靠性、正文可读性（字号、对比度）是契约层；字体、构图、色彩与表达强度是表达层。任何主题不得以降低正文可读性为代价维持人格。

## 二、分页面 / 组件修改方案

### 全局组件

| ID | 动作 | 理由 |
|---|---|---|
| G-1 | 主导航移除 Projects/Work 项，仅保留 Notes、Thinkings、Archive＋搜索＋主题切换；项目入口留在首页后段与 About。若任何位置保留入口，文案统一用 Projects（弃 Work，其语义暗示职业作品集） | 原则 1：主导航的三个栏目已完整覆盖「读」的职责，项目是「看」，权重平摊反而稀释内容栏目 |
| G-2 | 页脚删除「写作」「管理」两个作者侧链接；GitHub / RSS / Email 保留 | 访客会困惑自己是否也能发文；页脚服务对象是访客而非作者 |
| G-3 | 动效收束：Light 普通文本、日期、联系方式直接显示（移除 FlickerTitle 持续闪烁、About 联系方式解码、`data-scramble`）；列表逐项延迟入场改为一次性入场或删除；Dark 将强动效集中在首页光谱与字符签名两处 | 原则 3：闪烁和解码没有对应的可操作动作，是纯表演；动效预算应集中在少数记忆点 |
| G-4 | Light 滚动收拢的胶囊导航改为固定宽度、轻背景、去除宽度/形态变化 | 阅读过程中始终悬着一个变化的玻璃容器，与「进入内容后界面退后」的方向冲突 |
| G-5 | Dark 正文系统性调整：正文 17–18px、行高约 1.8、提高文字亮度；文章二级标题收至 28–30px；信息类小字（日期、返回操作、目录）对比度提至 ≥4.5:1，装饰性行号可豁免现状 | 原则 6：Dark 当前 36px 标题 vs 16px 弱色正文，界面比文章更想被读；`#71727b`（约 3.9:1）用于日期类信息低于可读底线 |
| G-6 | 清理字体声明与注释的不一致（注释描述 Fraunces，实际 token 指向系统无衬线）；衬线体只在首页一行文字／页尾摘抄做小范围试验，不全站替换 | 依据实际渲染做决策，避免在旧注释上继续叠加；文学气质优先落在「已经被选出来的文字」上 |

## 三、优先级与验收标准

### P0 — 信任层：网站不能说谎（先于一切审美改动）

| 项 | 验收标准 |
|---|---|
| `#projects` 双 id 锚点（关联 G-1） | 构建后 Light、Dark 各自访问 `/#projects` 均定位到项目区；每页渲染后 `id="projects"` 在 DOM 中唯一 |
| Dark 最新小记不可达（H-7） | Dark 首页可见或一键可达最新小记；两主题首页的「最新内容可达集合」一致 |
| 主题切换强制回顶＋删 hash | 在文章/列表中部切换主题后，滚动位置保留（同锚点或 \|ΔscrollY\| < 200px），URL hash 不被清除 |
| 搜索与筛选作用域（A-1/A-2） | ① 选「笔记」＋搜索「第二个」→ 结果区仅含笔记匹配；② 清空搜索 → 恢复时间归档；③ 搜索「留一点空白」→ 返回该小记且链接到 `/thinkings#<id>` |
| TOC 高亮中断（AR-3） | 在任一章节的长段落中部停留，其目录项保持高亮直至下一节接替；目录在展开/断点行为上移动与桌面一致 |

### P1 — 注意力与可读性

| 项 | 验收标准 |
|---|---|
| 首页重排（H-1~H-6） | 1440×1000 无滚动可见至少一个文章标题；DOM 无「关于我」按钮、无统计行；最近文章标题左对齐（与居中短句区形成两种节奏）；指向同一栏目的重复入口 ≤1；开场形态为「头像＋名字＋一句说明」（决策 A） |
| Dark 正文层级（G-5、TH-3、AR-2） | 正文 ≥17px、行高 ≥1.75、正文色对背景对比 ≥4.5:1；文章 h2 ≤30px；随想列表标题 28–32px；信息类小字 ≥4.5:1（装饰行号豁免） |
| 页面前导精简（N-1、AR-1、A-3/A-4） | Notes/Thinkings/Archive 首屏无滚动可见列表首项；列表页无「返回主页」（logo 承担）；Article 头部无路径重复、无浏览量；归档同一计数只出现一次、组内日期为月-日、筛选态下行无冗余分类标注 |
| 点击预期统一（TH-1/TH-2、N-2、PR-3） | DevTools 强制 `:hover` 下：Thinkings 非链接区域无视觉变化；不可点项目无光斑与 `cursor:pointer`；Notes 条目 hover 变化维度仅一种；「阅读全文」删除后标题静止态可辨识为链接（键盘 Tab 可达且有焦点样式） |
| 导航权重（G-1） | 主导航仅三栏目＋搜索＋主题；全站无 "Work" 文案 |

### P2 — 人格、表达与收尾

| 项 | 验收标准 |
|---|---|
| About 作者语言（AB-1/AB-2/AB-3） | About 首段存在占位文本「这里等待补充」（或已被作者替换为 2–3 句话），Monostich 含义至少出现一次；源码 grep 不到 `dev/curiosity`、`backend.service`、`sleep.service`；交互文案为「字符签名」 |
| Projects 降权（PR-1/PR-2） | 无四列网格；无闪烁状态灯；状态词仅限「未公开/可使用/停止维护」或删除；无链接项零 hover 反馈 |
| 动效收束（G-3） | Light 普通文本/日期/联系方式渲染后无持续动画；列表无逐项延迟入场（或总时长 ≤300ms 且一次性）；`prefers-reduced-motion` 下全部静止 |
| 页脚（G-2） | 访客视角无「写作/管理」链接 |
| 胶囊导航（G-4） | 滚动前后导航宽度不变、背景轻量、无形态切换（视觉评审通过） |
| 字体清理（G-6） | 注释与实际 token 一致；衬线试验仅出现在短句/摘抄区，正文仍是系统无衬线 |

## 四、实施顺序与红线

**顺序**：P0 一批 → P1 的「首页重排」与「Dark 正文层级」可并行（互不触碰同一文件集）→ 其余 P1 → P2。每批完成后在 Light/Dark 双主题、桌面视口下回归一遍 P0 验收项（改动集中在共享组件，P0 类问题最容易回潮）。

**明确不做**：

- 不加评论、点赞、推荐卡片、命令面板
- 不合并 Notes / Thinkings / Archive 三个栏目（职责清晰）
- 不全站换衬线体
- 不为填补空白增加模块
- 不抹掉 Dark 的光谱、行号、琥珀色与字符签名——它们是这套主题值得保留的记忆点；本方案只削减它们的「重复出场」，不削减它们本身
